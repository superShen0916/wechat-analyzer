# 错误处理

## 内部包

- 内部包向调用方返回错误，不得自行退出进程。
- 文件、解析、渲染和供应商错误使用 `%w` 保留原始错误，并增加简洁的中文
  操作上下文。参考 `internal/loader/json.go` 的 `LoadFile` 和
  `internal/report/html.go` 的 `GenerateHTMLReport`。
- 在包边界拒绝不可用输入，例如 `stats.AnalyzeConversation` 会拒绝 nil 或
  没有消息的会话。
- 即使 CLI 当前只打印错误文本，也要保留 `errors.Is` / `errors.As` 能力。

## CLI 边界

Cobra Handler 使用 `RunE` 返回命令级错误。导致整个请求无法继续的错误应直接
返回；批量处理时，单个文件失败可以警告后继续，参考当前 `walkPath`。

- 全局配置无效：返回错误并停止。
- 多个输入中的一个无效：打印警告并继续。
- 用户请求生成输出但目录不可写：明确报告该会话失败，不得声称生成成功。

只有 `main` 可以把最终错误转换为非零退出码。

## 敏感信息

- 错误可以包含输入路径和操作名称，不得包含 API Key 或消息正文。
- 供应商错误可以包装，但不要输出请求体、Header 或完整 Prompt。
- 测试应断言稳定行为或稳定片段，不要依赖第三方完整错误文本。

禁止 `panic`、忽略关键操作错误，以及在 `main` 之外调用 `os.Exit`。
